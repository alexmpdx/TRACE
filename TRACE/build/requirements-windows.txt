# Consolidated Python deps for the Windows PyInstaller build.
# Mirrors the union of requirements across LandmarkLocator, wingIsolator,
# modelTOjson, identifyFeatures, measurementMaker, and TRACE itself.
#
# torch is pinned to CPU wheels (no CUDA) — smaller download (~200 MB vs
# ~2 GB for GPU) and works on every Windows machine without a GPU.
# To switch to a CUDA build, replace the --index-url line with the
# appropriate one from https://pytorch.org/get-started/locally/.

# --- PyTorch CPU build -----------------------------------------------------
# Pinned to 2.4.1 because the latest torch wheels (2.5+) on Windows have
# had c10.dll DllMain init failures (WinError 1114) on otherwise-modern
# CPUs. 2.4.1 is the last known-stable release for PyInstaller bundling
# on plain Win11 client machines without CUDA.
--extra-index-url https://download.pytorch.org/whl/cpu
torch==2.4.1
torchvision==0.19.1

# --- Core scientific stack -------------------------------------------------
# numpy / shapely / onnxruntime are pinned as a coupled group because
# they're the only deps that have a hard numpy-1.x vs numpy-2.x ABI
# split. The CI build of v0.1.52 (onnxruntime==1.17.3 + unpinned numpy)
# failed loudly with
#     A module that was compiled using NumPy 1.x cannot be run in
#     NumPy 2.4.6 as it may crash.
#     AttributeError: _ARRAY_API not found
# at `import onnxruntime` — exactly the same numpy ABI mismatch that
# manifested at runtime in v0.1.50 as Windows error 1114
# (ERROR_DLL_INIT_FAILED) inside the frozen bundle. Build-time vs
# runtime symptoms differ but the root cause is the same.
#
# Resolution: align the whole stack on numpy 1.x.
#   - onnxruntime 1.17.3: last version with a clean PyInstaller bundle
#     AND built against numpy 1.x. Newer wheels (≥1.19) declare numpy
#     2 support but trip a different DLL-init issue in PyInstaller's
#     onedir layout (see prior commits chasing 1114).
#   - shapely <2.1: the 2.1 line dropped numpy 1.x wheels — its
#     compiled extension does `from numpy._core import umath` which
#     only exists in numpy 2.x. The 2.0.x line still ships numpy-1.x-
#     compatible wheels. v0.1.51 forgot this and produced an installer
#     that couldn't even open TRACE.
#   - numpy 1.26.x is the last 1.x release.
numpy>=1.26,<2
scipy
pandas
scikit-image
scikit-learn
# See the numpy comment above for why shapely is capped to the 2.0 line:
# shapely 2.1+ ships numpy-2.x-only wheels.
shapely>=2.0,<2.1
networkx
geojson
matplotlib
tqdm
pyyaml

# onnxruntime is pinned to 1.17.3: the latest 1.20+ wheels Microsoft ships
# fail to load inside PyInstaller bundles on otherwise-modern Windows
# machines with Windows error 1114 (ERROR_DLL_INIT_FAILED) — a transitive
# DLL's DllMain returns FALSE during onnxruntime_pybind11_state.pyd init.
# 1.17.3 (Feb 2024) is the last version widely confirmed to bundle cleanly
# via PyInstaller hooks; later versions add platform-feature detection
# during static init that interacts poorly with the loader's
# `os.add_dll_directory` search-path additions. If a future onnxruntime
# release fixes this, unpin.

# --- Networking ------------------------------------------------------------
# certifi ships the CA bundle that fetch_assets.py / the in-app updater
# point urllib at via ssl.create_default_context(cafile=certifi.where()).
# Without it, frozen Windows builds throw SSL: CERTIFICATE_VERIFY_FAILED
# on every HTTPS request because there's no reachable system trust store.
